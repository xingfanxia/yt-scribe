# YT Scribe

Chrome extension (Manifest V3) that copies, exports and chats with YouTube and Bilibili
transcripts. It is an independent reimplementation of the feature set of the "Copy Youtube Transcript"
extension (v1.7.1), with every feature unlocked and no backend, license server or analytics.

## Install

1. `chrome://extensions` → enable Developer mode → **Load unpacked** → select this folder.
2. Pin the extension. For AI chat, open its Settings and add an Anthropic API key
   (or an OpenAI-compatible endpoint + key).

## Features

| Surface | What it does |
|---|---|
| Popup | Copy transcript, export (Text / Markdown / PDF), live preview with word count, output format (timestamps, title, link, spacing, single paragraph, AI prompt prefix), named presets, history (most recent + searchable full list, copy again, open video, open chat, delete) |
| Popup settings (gear, in place) | Export button, preview, caption language (tracks of the current video), page buttons, history, auto-open AI site |
| Video page | Optional **Copy transcript** and **Ask AI** buttons next to Share on YouTube videos and Shorts, and at the end of the like/coin/favourite toolbar on Bilibili; progress and result shown on the button |
| Shortcuts | `Cmd/Ctrl+Shift+Y` copies the current transcript; `Alt+Shift+A` toggles the chat panel (change at `chrome://extensions/shortcuts`) |
| Side panel | Streaming AI chat grounded in the transcript; suggested actions (summary, takeaways, quotes, flashcards, quiz, simple explanation, claims, cited summary, open questions, social thread, blog outline, chapters, translate to 9 languages), one custom command, clickable `[m:ss]` timestamps that seek the video, copy / Markdown / PDF export, chat history per video |
| After copying | Optionally opens Claude, ChatGPT, Gemini, Perplexity or a custom URL (`{transcript}` placeholder) |
| Settings page | AI provider/key/model/endpoint/effort with a connection test, keyboard shortcuts |

UI strings are localized in English and Simplified Chinese (`_locales/`, generated by
`scripts/build-locales.py` — edit the table there, not the JSON).

## How transcripts are fetched

`src/content/extract.js` tries sources in order and returns the first non-empty result:

1. The live player response (read in the page's MAIN world, so it follows SPA navigation),
   falling back to parsing `ytInitialPlayerResponse` from the watch page HTML.
2. The chosen caption track's `timedtext` URL (`fmt=json3`).
3. The same URL with a PoToken captured by toggling captions and reading the player's own request.
4. Caption tracks from the Innertube `player` endpoint with Android / iOS client contexts.
5. The `get_transcript` endpoint with params from `ytInitialData`.
6. YouTube's own transcript panel, read from the DOM.

Track choice: saved language → browser languages → English → first manual track; manual
tracks win over auto-generated ones. Errors map to `err_*` messages (private/age-restricted,
live, unavailable, rate-limited, no captions, Shorts without captions, clipboard blocked).

## How Bilibili subtitles are fetched

`src/content/extract-bilibili.js` handles `/video/BV…|av…` (with `?p=` parts), `/list/…?bvid=`
and `/bangumi/play/ep…`:

1. `x/web-interface/view` (or `pgc/view/web/season` for episodes) gives the `cid` and title.
2. `x/player/wbi/v2`, signed with WBI (`signWbi` + `md5` in `core.js`; keys from
   `x/web-interface/nav`), lists the subtitle tracks; unsigned `x/player/v2` is the fallback.
3. The chosen track's JSON (`body[].from/content`) becomes the transcript.

Bilibili returns subtitles only to signed-in users (`need_login_subtitle`), so all requests run
in the content script on www.bilibili.com and carry the browser's own login cookies; signed out,
the extension reports `err_login_needed`. In automatic language mode it keeps uploader tracks,
then the original-language AI track (listed first); the other AI tracks are machine translations.

## Differences from the original

- Bilibili support (the original handles YouTube only).
- No Pro tier, license activation, free-chat quota, upgrade prompts, uninstall survey,
  feedback mailto or usage analytics.
- AI chat calls the provider directly with your own key (Anthropic Messages API with prompt
  caching on the transcript, or any OpenAI-compatible `/chat/completions`) instead of a vendor
  backend, and streams the answer. The transcript is sent with timestamps so citations link back.
- PDF export downloads a real PDF in one click (`src/shared/pdf.js`, pdfkit) with subsetted
  Noto Sans + Noto Sans SC, so Chinese and Japanese render (the original's font is Latin-only).
  Text neither font covers (Hangul, Arabic, Thai, …) falls back to the print view.
- History stores the transcript itself, so "Copy again" and old chats work offline.
- Model replies are rendered through an escaping Markdown renderer (no raw HTML injection).

## Layout

```
manifest.json
src/background.js          service worker: MAIN-world helpers, side panel toggle, commands
src/content/               extract.js (YouTube), extract-bilibili.js, content.js (message API, page buttons), content.css
src/shared/                core.js (pure helpers), markdown.js, store.js, dom.js, ai.js
src/popup/ src/sidepanel/ src/options/ src/print/ src/ui/theme.css
src/vendor/                pdfkit standalone build (see src/vendor/README.md)
_locales/ icons/ fonts/ scripts/ test/
```

Shared files are classic scripts attached to `globalThis.YTS` because content scripts cannot
be ES modules. `core.js` and `markdown.js` also export via `module.exports` for Node tests.

## Development

```sh
npm install          # Playwright for the e2e test, pdfkit source for src/vendor
npm test             # unit tests (node --test)
npm run e2e          # live YouTube + Bilibili smoke test, screenshots/PDFs in scratch/media/e2e/ (needs poppler)
ANTHROPIC_API_KEY=... npm run e2e   # also exercises streaming chat and timestamp seeking
BILI_COOKIES=cookies.json npm run e2e   # signed-in Bilibili flow (Playwright cookie JSON for .bilibili.com)
```

Without `BILI_COOKIES` the Bilibili part only checks the signed-out path. The cookie file holds a
live login session: keep it in the ignored `scratch/` folder and delete it after the run.

The e2e script loads the unpacked extension in Playwright's full Chromium (`channel: "chromium"`,
new headless); the default headless shell cannot load extensions. YouTube changes its page
structure often — when copying breaks, run `npm run e2e` first; the `source` it prints shows
which fallback still works.
